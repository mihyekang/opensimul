01 프로젝트 개요

OpenSimul은 가족 단위의 가계부 관리를 돕는 AI 어시스턴트입니다. 영수증 이미지 또는 텍스트를 AI가 자동으로 파싱하여 구매 품목·금액을 추출하고, 채팅 인터페이스를 통해 지출 패턴 분석·질의응답을 제공합니다.

🧾
영수증 자동 인식
이미지(JPG·PNG·PDF) 또는 텍스트를 Azure OpenAI GPT-4o/mini 로 파싱. 상점명·날짜·품목·금액을 구조화된 JSON으로 추출합니다.
💬
AI 채팅 가계부
자연어로 지출 내역을 질문하고 분석받습니다. 최근 7일 구매 이력을 매 턴마다 컨텍스트로 주입해 항상 최신 상태를 반영합니다.
👨‍👩‍👧
가족 공유
사용자 코드를 가족끼리 공유해 구매 이력을 함께 관리합니다. PBKDF2+salt 방식의 안전한 비밀번호 인증을 제공합니다.
📋
이력 관리
저장된 모든 영수증을 패널에서 조회·확대·삭제할 수 있습니다. 삭제 시 LLM 대화 이력에도 자동으로 동기화됩니다.

02 시스템 아키텍처

FRONTEND
  • 채팅 UI (index.html)
  • 영수증 가져오기 (grocery.html)
  • 인증 오버레이 모달
  • 영수증 이력 패널
  • 모드 탭 (이미지 / 텍스트)
BACKEND — FastAPI
  • 채팅 스트리밍 SSE
  • 영수증 추출 (이미지/텍스트)
  • 이력 조회 · 삭제
  • 세션 관리
  • 인증 (login/register)
DATABASE — PostgreSQL
  • users
  • sessions / messages
  • grocery_receipts
  • grocery_items
  • image_analyses
AZURE OPENAI
  • GPT-4o (vision: 영수증 인식)
  • gpt-5.4-mini (채팅 · 텍스트 파싱)
  • 슬라이딩 윈도우 이력
  • transient 컨텍스트 주입

AUTH-06 로그아웃 localStorage 초기화 후 인증 모달 재표시. Should 완료

EXT-09 상점명 매핑 이마트·롯데마트·홈플러스·쿠팡·네이버쇼핑 등 20여 개 상점 시그널을 정규식·키워드로 표준명 매핑. Should 완료

3.3 영수증 저장 및 이력

ID요구사항상세우선순위상태
SAVE-01 개별 저장 결과 카드마다 "이 영수증 저장" 버튼. 저장 후 버튼 상태 변경(✅ 저장됨). Must 완료
SAVE-02 일괄 저장 미저장 영수증 일괄 저장 후 채팅 페이지로 이동. 채팅에서 자동 요약 트리거. Must 완료
SAVE-03 이력 패널 햄버거 메뉴 하위 "영수증 이력" 패널. 전체 저장 목록을 날짜·상점·합계로 표시. Must 완료
SAVE-04 아코디언 상세 보기 카드 클릭 시 품목 테이블 확장(max 320px 스크롤). 접으면 첫 줄 텍스트 클리핑 없음. Should 완료
SAVE-05 사용자 격리 모든 DB 쿼리에 user_id 조건 추가. 다른 사용자 영수증 조회·삭제 불가. Must 완료

3.4 영수증 삭제

ID요구사항상세우선순위상태
DEL-01 채팅 트리거 삭제 "잘못 올렸어", "중복으로 저장했어", "삭제하고 싶어" 등 자연어 패턴 감지 시 삭제 UI 표시. Must 완료
DEL-02 삭제 UI 목록 영수증마다 #ID·상점명·날짜·합계를 표시. 건별 🗑 버튼으로 삭제. Must 완료
DEL-03 이력 패널 체크박스 삭제 🗑 삭제 버튼 토글 → 체크박스 활성화 → "선택 삭제 (N)" 확인 버튼. Must 완료
DEL-04 LLM 이력 동기화 삭제 성공 시 /chat/note를 호출해 LLM 대화 이력에 삭제 사실 주입. 이후 채팅에서 삭제된 영수증을 참조하지 않음. Must 완료
DEL-05 소유자 권한 검증 DELETE 요청 시 user_id 일치 여부 서버에서 검증. 불일치 시 not_found 반환. Must 완료

3.5 AI 채팅

ID요구사항상세우선순위상태
CHAT-01 스트리밍 응답 SSE(Server-Sent Events)로 토큰 단위 실시간 스트리밍. 오류 시 일반 POST fallback. Must 완료
CHAT-02 구매 컨텍스트 주입 매 채팅 턴마다 최근 7일 구매 이력을 system prompt에 자동 주입. 영수증 삭제 후 즉시 반영. Must 완료
CHAT-03 슬라이딩 윈도우 이력 최근 N 턴만 LLM에 전달(설정 가능). DB에서 세션 복원 지원. Should 완료
CHAT-04 대화 초기화 세션 리셋 시 인메모리 이력 초기화 + DB 메시지 삭제. Should 완료
CHAT-05 영수증 카드 렌더링 "영수증 보여줘" 등 패턴 감지 시 구매 내역을 상점별 카드 형태로 채팅창에 렌더링. Should 완료
CHAT-06 사용량 표시 매 응답 후 토큰 수·턴 비용(KRW)·누적 비용 표시. Nice 완료
CHAT-07 메모리(기억) 사용자 정보를 키-값으로 저장해 모든 세션에 걸쳐 system prompt에 반영. Nice 완료
CHAT-08 LLM 노트 주입 POST /chat/note로 LLM 호출 없이 대화 이력에 직접 턴 삽입 (삭제 동기화 등 내부 알림용). Must 완료

04 API 명세

인증

엔드포인트설명요청 Body응답
POST/auth/register 회원가입 user_code, password ok, user_code, reason
POST/auth/login 로그인 user_code, password ok, user_code, reason

채팅

엔드포인트설명요청 Body응답
POST/chat 일반 채팅 message, session_id, user_id reply, usage
POST/chat/stream 스트리밍 채팅 (SSE) message, session_id, user_id data: {token} · data: {usage}
POST/chat/note LLM 이력 노트 주입 session_id, user_note, assistant_note ok
POST/reset 대화 초기화 session_id, system_prompt ok

메모리

엔드포인트설명
GET/memory메모리 조회 (session_id 쿼리)
POST/memory메모리 항목 저장 (key, value)
DEL/memory/{key}메모리 항목 삭제
DEL/memory메모리 전체 삭제

영수증

엔드포인트설명비고
POST/grocery/extract 이미지/PDF 영수증 추출 multipart/form-data, image 필드. GPT-4o vision 사용.
POST/grocery/extract-text 텍스트 영수증 추출 JSON body, text 필드. gpt-5.4-mini 사용.
POST/grocery/save 영수증 DB 저장 result(dict), user_id. receipt_id 반환.
GET/grocery/history 영수증 목록 조회 days(기본 30), user_id 쿼리 파라미터.
GET/grocery/recent 최근 영수증 조회 (채팅용) days(기본 90), user_id. 채팅 카드 렌더링에 사용.
GET/grocery/receipt/{id} 영수증 상세 조회 품목 목록 포함. user_id 권한 검증.
DEL/grocery/receipt/{id} 영수증 삭제 소유자(user_id) 일치 시만 삭제. ok/reason 반환.

05 데이터 모델

-- 사용자 CREATE TABLE users ( user_code TEXT PRIMARY KEY, -- 로그인 ID (가족 공유 가능) password_hash TEXT NOT NULL, -- PBKDF2-SHA256:salt:hash created_at TIMESTAMPTZ DEFAULT NOW() ); -- 채팅 세션 CREATE TABLE sessions ( session_id TEXT PRIMARY KEY, created_at TIMESTAMPTZ, last_active TIMESTAMPTZ ); -- 대화 메시지 CREATE TABLE messages ( id SERIAL PRIMARY KEY, session_id TEXT REFERENCES sessions ON DELETE CASCADE, role TEXT, -- 'user' | 'assistant' content TEXT, created_at TIMESTAMPTZ ); -- 영수증 헤더 CREATE TABLE grocery_receipts ( id SERIAL PRIMARY KEY, user_id TEXT NOT NULL DEFAULT '', -- 소유자 user_code purchase_date DATE, merchant TEXT, total INTEGER, -- KRW, 원 단위 currency TEXT DEFAULT 'KRW', is_refund BOOLEAN DEFAULT FALSE, raw_json JSONB, -- LLM 원본 응답 created_at TIMESTAMPTZ ); -- 구매 품목 CREATE TABLE grocery_items ( id SERIAL PRIMARY KEY, receipt_id INTEGER REFERENCES grocery_receipts ON DELETE CASCADE, raw_name TEXT, -- 영수증 원문 품목명 qty INTEGER, unit_price INTEGER, -- 단가 (null 허용) amount INTEGER, -- 음수 = 할인 is_cancelled BOOLEAN );

06 비기능 요구사항

🔒 보안
비밀번호 PBKDF2-SHA256 해시 저장.
모든 영수증 API에 user_id 소유자 검증.
SSL 설정 가능(환경변수).
⚡ 응답성
채팅 SSE 스트리밍으로 첫 토큰 즉시 표시.
동기 DB 호출은 run_in_executor로 비차단.
이미지 전처리로 API 지연 최소화.
📐 확장성
SessionManager 최대 100 세션 캐시.
7일 이상 비활성 세션 자동 정리.
DB 미연결 시 메모리 모드로 동작.
🔄 일관성
영수증 삭제 시 LLM 이력 자동 동기화.
채팅 매 턴마다 DB 기반 컨텍스트 갱신.
삭제된 항목은 이후 LLM 응답에서 제외.
🧩 이식성
.env 파일 기반 환경 설정.
requirements.txt 의존성 고정.
Azure Key Vault 이전 예정.
📱 접근성
모바일 viewport 대응 CSS.
좁고 긴 스크린샷(≤400×6000px) 원본 유지.
드래그앤드롭 + 클릭 양방향 입력.
